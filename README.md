# NightRunApp

React + TypeScript + Vite. Проект организован по Feature-Sliced Design (FSD).

## Структура

```text
src/
  app/                  # Сборка приложения, провайдеры, роутинг, глобальные стили
    App.tsx
    providers/router/index.tsx # BrowserRouter и маршруты
    styles/index.scss
  pages/                # Страницы приложения
    home/
      index.ts          # Публичный API слайса
      ui/HomePage.tsx
    not-found/          # Страница для неизвестных адресов
  main.tsx              # Точка входа React
```

По мере появления функциональности добавляем слои `widgets` (крупные блоки
интерфейса), `features` (действия пользователя), `entities` (бизнес-сущности)
и `shared` (общий UI, библиотеки, конфигурация и инфраструктура без бизнес-логики).
Пустые слои заранее не создаём.

## Правила зависимостей

- Порядок слоёв сверху вниз: `app → pages → widgets → features → entities → shared`.
- Модуль может импортировать модули только из нижележащих слоёв.
- Слайсы одного слоя не импортируют друг друга.
- Внешние импорты слайса идут через его публичный API (`index.ts`).
- Внутри слайса используем относительные импорты напрямую, без собственного `index.ts`.
- Сегменты `ui`, `model`, `api`, `lib`, `config` добавляем по необходимости.
- Слои `app` и `shared` делятся на сегменты без бизнес-слайсов.
- Логику одной страницы оставляем в её слайсе, пока не появится причина
  выделить самостоятельный нижележащий модуль.

## SPA и маршрутизация

React Router подключён в `app/providers/router`: `/` открывает главную,
`*` показывает страницу 404 со ссылкой на главную. Новые страницы добавляем
в `pages`, а маршруты регистрируем в `app/providers/router/index.tsx`.
Для внутренних переходов используем `Link` / `NavLink` из `react-router`.

На production-хостинге необходимо настроить возврат `index.html` для адресов
приложения, которые не соответствуют статическим файлам. Это позволяет открывать
вложенные маршруты напрямую и обновлять страницу. Vite dev server поддерживает
SPA fallback по умолчанию.
